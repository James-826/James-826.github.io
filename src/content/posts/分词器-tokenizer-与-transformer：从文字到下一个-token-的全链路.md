## 一、分词器存在的意义

分词器的意义，就是把人类的自然语言转换成机器可以理解的数字。

大模型本质上是一个巨大的计算器，它只做矩阵运算、只认数字，吃不下 "transform" 这种字符串。所以必须在「人看的文字」和「模型吃的数字」之间架一座桥——这座桥就是分词器。

一句话：分词器 = 翻译官，负责把文字 ↔ 数字做双向映射。

## 二、分词器的训练过程（以 BPE 为例）

分词器不是天生就会切词的，它是先在大规模语料上「预训练」出一份词表 + 合并规则，之后冻结、直接拿来用。以最常见的 BPE 为例，训练过程是这样的：

1. 扫描整个语料，统计相邻单元「出现次数最多的组合」，把这个组合合并成一个新单元，再给它分配一个新的 id、写进词表；
2. 先把每个词拆到最小单元给每个最小单元分配一个数字 id
3. 重复第 3 步，直到词表达到目标大小或者合不动为止。

举个中文直觉例子（和英文字母同理）：语料里「人」和「工」挨着出现的次数最多，就把它们合并成「人工」，分配新 id；再扫描，「人工」和「智能」又最常挨着，合并成「人工智能」——四个字就从「人/工/智/能」逐步合成了「人工智能」这个词。

> 💡 **补充（校准一个点）**：第 1 步说的「最小单元」，对 BPE 来说其实是单个字符（英文是 26 个字母，中文是单字），不是「最小的单词」。因为 BPE 的思路就是「从字符出发，一步步往上合并出有意义的子词」。你写的「最小的单词」在 word-based 思路里成立，但在 BPE 这条子词路线上，起点是字符。
>
> 💡 **补充（推理时怎么用这份词表）**：训练完之后，词表 + 合并规则就固定了。运行时分词器不再重新合并，而是直接拿这套规则去查表——比如 WordPiece 做「贪婪最长前缀匹配」：遇到 "Transformer"，先在词表里找能匹配的最长子词 "Trans"，剩下的 "former" 再找 "##former"，于是切成 Trans + ##former。所以你总结的「先分词、再根据规则合并、最后通过词表映射成数字」——方向完全对，只是「合并」这件事主要发生在训练造词表时，推理时是「查现成规则 + 查表」。

## 三、分词器的三种形态（演进）

分词器不是一上来就是子词合并的，它经历了三个阶段：

**1. 按单词切（word-based）**

最传统的方式，比如按空格把句子切成单词："i love you" → \[i, love, you]。

问题有三个：

* **词表太大**

  ：英语 50 多万个单词，词表就要这么大，每个词在模型里还占一行；
* **生词没法处理**

  ：词表里没见过的词直接打成 \[UNK]，整词信息丢失；
* **不同词之间没有语义关系**

  ：比如 unhappy 和 happy 各自一个 id，模型一开始不知道它俩有关，当成陌生人。

**2. 按字符切（character-based）**

把句子拆成单个字母："transformer" → \[t, r, a, n, s, f, o, r, m, e, r]。

优点：词表极小，只有 26 个字母，永远不会出现 \[UNK]。

问题：单个字符没有意义——字母组合成单词才具有语义。t 单独几乎没含义，只有 transform 整体才有「转换/变形」的意思。而且一个词被拆成十几个 token，序列超长、算力翻倍。

**3. 按子词切（subword，BPE / WordPiece）**

折中方案。常用词整体保留，生僻 / 长词才拆成有意义的碎片。比如 transformer 拆成 transform + er，这样 transform 和 transfom（或 transforming 等）就在数字 id 上产生了关联；词表数量又不会像单词那样爆炸。

> 💡 **补充（校准一个直觉）**：你说「子和 transform 具有了数字上的一个关联」——准确说是共享子词让它们在向量空间里共用同一段表示，模型因此能自动学到「这些词有关、un 是否定、er 是后缀」这类形态关系。这是子词相对 word-based 最大的赢点。另外注意词表大小排位是：字符(26) < 子词(~3万) < 单词(50万+)，子词在「甜点区」，不是最小。

## 四、分词器的编码与解码（运行时）

分词器分两半：

* **编码（Encoder）**

  ：把句子分词 + 映射成数字 id。比如 "i love you" → \[1, 2, 3]。这一步只在输入时做一次。
* **解码（Decoder）**

  ：把模型输出的数字 id 映射回单词，变成人能看的文字。比如 \[1, 2, 3] → "i love you"。

> 💡 **补充（两个「解码器」别混！这是最容易踩的坑）**：上面说的「分词器的解码」= decode()，干的是 id → 文字字符串，纯给人看的显示，不参与任何计算。后面 Transformer 里还会提到「解码器（Decoder）」，那是 Transformer 架构里的一个模块（GPT 类模型就是 Decoder-only），里面含「带 Mask 的自注意力」。这两个「解码器」不是一回事，名字撞了而已。
>
> 💡 **补充（解码是整体转换，不是流式逐 token 合并）**：decode() 拿到的是「当前已经累积的完整 id 列表」，一次性查表、按 ## 标记拼接成文字（如 Trans + ##former → Transformer）。它不「等下一个 token 来判断要不要合并」——## 标记本身就写在 token 上，看到就拼。你之前以为「分词器也是自回归的、逐 token 输出」，其实自回归循环在模型里，分词器只是无状态映射器：模型每吐一个 id，就直接 append 进列表、再整体 decode 一次给人看。

## 五、从 ids 到向量：Embedding

分词器映射出来的 ids 还不能进模型算，得先变成向量。

ids 通过 Embedding 嵌入层生成高维度的向量。比如句子 "i love you" 的 \[1, 2, 3]，每个 id 去 Embedding 矩阵里查对应的一行，就都变成了高维向量（BERT 是 768 维）。

> 💡 **补充（含义存在哪）**：词表只是「门牌号字典」（id ↔ 子词字符串），真正的含义在 Embedding 矩阵里——id 是「第几行」的货架号，模型吃的是那一行 768 维向量，不是字符串也不是 id 本身。

## 六、Transformer 核心：自注意力 + Q / K / V

拿到每个词的向量后，Transformer 用自注意力让每个词「环顾全句」，把相关上下文融进自己的向量里（这就是你 Task 1 学的「attention 更新向量」）。

机制是：每个词的向量分别乘上三个转换矩阵 W_Q、W_K、W_V，映射成三组向量：

* **Q（Query，查询向量）**

  ：「我在找什么」；
* **K（Key，键向量）**

  ：「我身上是什么标签」；
* **V（Value，值向量）**

  ：「我实际贡献的内容」。

计算分四步：

1. **打分**

   ：用 Q 和所有词的 K 做点积（Q·Kᵀ），得到每个词之间的相关性分数；
2. **缩放**

   ：除以 √d（d 是向量维度），防止分数过大；
3. **归一化**

   ：过 Softmax，把分数变成「和为 1 的权重」；
4. **加权求和**

   ：用这些权重去乘各自的 V，再加起来，得到融合后的新向量 Z。

> 💡 **补充（校准一处表述）**：你说「Q 和 K 组合成矩阵计算，就把 K 的内容嵌入进了每个单词向量内部」——这里要改准：K 只负责「匹配」（决定谁和谁相关、相关性多高），真正被搬进新向量的是 V（Value）的内容。直觉是：Q·K 算出「我该关注你多少」，Softmax 之后乘 V 才是「把你多少内容搬过来」。所以准确说法是「Q·K 决定权重，×V 才把相关上下文融入查询向量」。
>
> 💡 **补充（相关性例子是对的）**：你说的「you 的 Q 和 love 的 K 相关性高、数值就高」完全正确——句子里 "you" 和 "love" 语义相关，它们的 Q·K 分数高，Softmax 后权重就大，love 的 V 就被更多地混进 you 的新向量里。这正是注意力消解一词多义、理解上下文的机制。

## 七、为什么要除以 √d

Q·K 的点积结果，方差大约会随着维度 d 线性增长（d=64 时方差≈64、标准差≈8）。如果不除以 √d，打分就会落在像 -24~+24 这么大的范围，丢进 Softmax 后直接饱和——某一项趋近于 1、其他趋近于 0，导致梯度几乎为 0，模型学不动（梯度消失）。

除以 √d（如 √64=8）把方差拉回 1、打分落在 -3~+3，Softmax 输出健康、梯度能正常回传。

记忆：不除 √d → 方差爆炸 → Softmax 饱和 → 梯度消失；除 √d → 数值稳定 → 能学。

## 八、注意力如何参与生成（自回归）

模型预测下一个 token 时，靠的是自注意力把上下文融进每个词的向量，然后用序列最后一个位置的输出去做预测。

具体生成节奏（解码器 / Decoder-only 模型）：

* 当前所有 token 通过自注意力互相看（但带因果掩码，不能看未来）；
* 取最后一个位置输出的向量，过 Linear + Softmax 在词表上打分，概率最大的那个 = 下一个 token；
* 把这个新 token 的 id 拼回序列，再走一轮——这就是自回归循环。

为了防止「作弊」（生成时偷看后面的词），解码器会对「未来位置」打上 Mask 掩码，设为负无穷，这样 Softmax 之后它们的权重就是 0，等于看不见。

> 💡 **补充（校准「根据最后一个词」的说法）**：不是「只根据最后一个词」，而是每个位置都通过注意力融合了它之前所有位置的上下文；预测时我们取的是「最后一个位置」输出的向量去算下一个词。另外这个 Mask 只存在于生成侧（Decoder），输入侧的编码（Encoder）注意力是不加 Mask 的——因为输入整句都已经给了。

## 九、一句话串起全链路

句子 → 分词器编码（文字→ids）→ Embedding（ids→向量）→ +位置编码（补词序）→ 自注意力（Q/K/V 更新向量，融入上下文）→ 残差/LayerNorm + FFN 堆叠 N 层 → Linear → Softmax（词表上打分）→ 概率最大 = 下一个 token → 自回归循环 → 分词器解码（ids→文字给人看）。
